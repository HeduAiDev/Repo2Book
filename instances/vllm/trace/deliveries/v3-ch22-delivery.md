## Why it matters

Part V 收官章：执行臂与 KV 池的接缝整块点亮，块号到槽位的最后一条线接通。四半边交割——CPU 半边：行长账+五原语差量维护一张 CPU/GPU 双镜像页表，commit 只拷活跃行且抢在 `_prepare_inputs` 第一句发车（H2D 与 CPU 活重叠，非活跃行迟到写不上镜像的 88 反证）；GPU 半边：一个 Triton kernel `grid=(num_reqs+1,)` 把恒等式与 PAD 重填一次算完，positions 进、slot_mapping 出、全程不落 CPU（D2H 禁忌最著名的反面案例正面立起——ch12 deprecated 措辞+VLLM_GPU_SYNC_CHECK 两处白纸黑字的落点），do_not_specialize 把每拍可变的 num_tokens 从特化缓存键除名防热路径重编译，qsl 非递减+区间互斥给出「无重无漏全量重写」论证（残留寿命≤一拍）；装配半边：padded/unpadded 双口径按两个静态开关裁决（KV 写独立成 op 或 FULL 图档任一成立即 padded——写 kernel 以 slot_mapping 形状定 token 数、-1 段被跳过故 padded 无害），块表尾行补 0、slot 尾段补 -1，一起进 CommonAttentionMetadata 与 ForwardContext 逐层铺设；消费半边：写腿 reshape_and_cache_flash 每 token 一次直寻址（逆分解 slot//bs、slot%bs 拆回块号行号），读腿 flash_attn_varlen_func 穿表间接寻址——**F7 在此结账**：写 O(1) 与表长无关（写只碰本拍新 token）、读表随请求长大（读要全部历史），分页买来的利用率（20.4%-38.2%→满池 2-4 倍）税就交在读腿，对拍 5.96e-08 写直读间闭合。三个开篇问题全部收口且各有实测（空槽不写花池=每拍重填 -1+slot<0 跳过，真 token 落块 3、未分配池块一字节不动）。PAD 语义上升为方法论：同一哨兵手法、两个值域、两种落地（-1 天然免检 vs 0 靠 null_block 让位）。DCP 交错分片三件单卡全退化恒等——同一 kernel 服务所有部署形态。Part V 六章至此收官（ch17 三层骨架→ch18 固定地址→ch19 编译捕获→ch20/21 注意力数学与后端→ch22 接缝），下一程 Part VI 模型定义层。
