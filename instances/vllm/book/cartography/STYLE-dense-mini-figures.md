# 风格规范：密集小图算法讲解（v3，2026-09-16 用户指定）

> **样板**：知乎《手撕 DeepSeek-V4 (3): HCA（Heavily Compressed Attention）》（小冬瓜AIGC 系列）。
> 抓取稿存档：`instances/vllm/book/papers/ch28-deepseek-v4-principles/refs/shou-si-v4-3-hca.md`（19 图 / ~40K 字）。
> **本规范约束：原理章（primer）与一切「讲算法」的节的图与讲解结构。**
> 用户原话：「使用密集小图解释算法，而且每张图都是必要的」。

## 一、样板的结构套路（已从抓取稿逐节提取）

模块拆解 = **六段式**，每个模块（如 Compressor / HCA）都走一遍：

1. **问题定义**（这步要解决什么，为什么难）
2. **原理**（最小机制的直觉 + 公式）
3. **渐进实现**：`sec1_基础版 → sec2_加机制 → sec3_再进一步 → sec4_完整版`——**每一步一个小文件/小段**，读者跟着长出来
4. **完整实现**（真实代码，带分节注释：`# 1. …  # 2. …`）
5. **状态维护**（这个模块在 prefill/decode 两侧各维护什么状态、怎么滚动/复位）
6. **分析**（与邻居架构对比：HCA vs MLA / vs NSA/DSA/CSA，最后给「洞察」）

## 二、图的三条硬规则（本规范的核心）

1. **密集**：样板约 **每 2000 字一张图**（40K 字 19 图），且**按步骤逐张推进**——不是章节末尾凑几张全景图，而是「讲一步、配一图、再下一步」。本项目对原理章的配额：**每个六段式模块 3-6 张小图**（按步骤数配，一步一图）。
2. **每张图都是必要的**：判据 = **删掉这张图，该步的论证就断**（读者无法从文字补出来）。满足不了 → 不画。**禁止**：装饰图、重复图（同一论点的第二个画法）、与文字互不依赖的「配图」。
3. **小图**：每图一个论点、聚焦单一步骤/单一量（如「环形缓冲怎么写」「压缩块与窗口 token 怎么重叠」各一张）。**不画大而全的合成图**——章级全局由 L2/L1/L0 负责（一层图原则不变：机制小图是「步进图」，不是第二种架构画法）。

## 三、文字侧配套条款

- **图贴在该步旁边**：正文讲到哪一步，图就在那里（`![…](…)` + 紧跟一行图注）；**图注 = 该步的结论**（不是描述画面），必要时给该步的关键数。
- **极小数值例内联**：每个机制配一个手算级例子（样板规格：`L=11, r=4, offset=0` 这种），数字必须与 trace 一致；例子紧贴机制，不攒到章末。
- **渐进实现的两个载体**：真实源码（本仓 pin）+ **伪码阶梯**（`sec1 基础 → sec2+门控 → sec3+触发 → 完整`）。伪码与真实代码同名同结构，只做减法/去枝，让读者把「机制骨架」和「工程枝节」分开看。
- **分析节收尾**：每个大模块结束时给「对比 + 洞察」（与邻居方案比：差在哪、换来什么），这是样板的「4. 分析 / 4.4 洞察」。

## 四、与现有图系/契约的关系

- L0/L1/L2 三层缩放**不变**（一张图原则）：机制小图属 L2 之下的「步进图」层，必须能回答「它是 L2 章图哪一拍的放大」。
- 与 WRITING-CONTRACT-v3 §2「先地图后细节」并存：章图（L2/L1）开局定位，步进小图随讲随出。
- 与技术图规约并存：配色/字体仍取 `l0_common.py` 常量；盲审门禁照旧（只看 PNG+spec，核论点/数字）。
- **配额校验**（写作自查）：本章小图数 / 正文千字数 ≥ 0.4（每 2500 字至少一图）；任一图答不出「删了论证就断」即删。
