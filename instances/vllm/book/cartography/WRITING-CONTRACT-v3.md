# v3 写作契约（vllm 重写版，Write 站注入）

> 依据：spec 四要素 + 用户裁决（hook/先原理后代码/阶梯认知/不淹没细节）。
> 本契约由 chapter-pipeline-v3 的 Write 站注入 writer；违反任一条 = reviewer 打回。

## 1. hook 开篇（替代「本章介绍 X」）

每章第一段必须是**一个真问题**（pedagogy-plan 的 hook 字段为基准，可润色但不许降格成陈述句）。
读者带着问题读——问题本身要能戳中困惑（好：「俩字凭啥跑两趟跨进程快递？」坏：「本章介绍 IPC 机制」）。
开篇三件套顺序：**hook → 本章地图（L2 图）→ 进入正文**。

## 2. 先地图后细节

- 开篇 `## 你在这里` 段放本章 **L2 章图**（Part 首章先放 L1 再 L2）。
- 图注三要素（缺一 reviewer 打回）：①这块在 L0 全局图的哪里（认得感——「它就是第 1 章那张图里的 XX 块」）；
  ②本章打开什么、接在哪几块已读结构上；③站号 = 请求流经代码的顺序，正文按讲解需要编排、不必照站号读。
- 正文任何时刻进入新组件，先一句「现在走到 L0 图的哪一段」再展开细节。

## 3. 阶梯不跳级（概念首现门禁）

- 本章 `introduces` 清单（pedagogy-plan）里的概念：**在本章首次出现处讲透**（好奇专家声线，writer.md 必达物 #9）。
- 清单外的非常识概念若前章已立：直接用+规范跨章链接，**不许重讲**（重讲=节奏塌）。
- 若发现正文需要某概念但其前置未立（本章与前章都没讲透）：拉逃生舱 BLOCKED 报 Lead 调整大纲，**不许硬写**。

## 4. why 链四要素（叙事骨架）

每个设计决策的讲述必须含：**旧设计是什么 → 痛点（哪个指标被卡，有数字更好）→ v1 方案（file:line）→ 代价（诚实！）**。
素材唯一来源：本章对应的 `deepread/*.json` 卡（行号已对 v0.27.1 核验）+ 本章 dossier。
四要素不许砍成「v1 是怎么做的」单向陈述——没有旧设计与代价的对照，读者建立不了判断力。

## 5. 伏笔埋设/回收（pedagogy-plan 驱动）

- 本章若是某伏笔的 `planted` 章：在自然位置埋（不刻意），措辞留钩子（「这个机制后面还会回来」级即可）。
- 本章若是 `paid` 章：回收时显式回指（「第 N 章埋的 X，现在看清了」），跨章链接规范照 lint_anchors。

## 6. v2 源码段迁移规则

- 允许迁移 v2 章的源码解读段（v2 映射见大纲末列），**但每一处须对 v0.27.1 现核**：
  行号漂移/符号改名/机制重构（§0.5 演进速览 13 条是高发区）一律以新 pin 为准。
  - v2 的行号是 v0.21.0 的——**逐段对源码确认后才可落笔**，禁止照抄行号。
  - 被重构的机制（elastic EP/xgrammar 面/partial CoW 等）：按 deepread 新卡重写，不迁移旧叙述。
- 迁移的是**源码事实与走读结构**，叙事骨架（hook/地图/阶梯/why 链）全部按本契约重写。

## 6.5 内嵌片段行号锚注（2026-08-21 用户定：「片段没绝对行号、正文引用 Lxxx 很难读」）

- 正文引用片段内某行时，**在该行行尾加锚注 `# Lnnn`**（nnn=该行在 pin 源码的真实行号）——读者扫片段立即定位，正文说「L439」不再悬空。
- **只加承重行**（正文讲解点到的行/读者需按图索骥的行），禁全篇行号噪音。
- 格式：行尾两空格 + `# L439`；如该行已有源码注释，锚注接在注释后（`x = 1  # 已有的话  # L2270` 不行——合并为 `x = 1  # L2270 已有的话` 或把锚注放最前）。实际规范简化：**锚注独立成尾注 `  # Lnnn`，与既有注释之间用一个空格隔开亦可**，lint_fidelity 的注释剥离对两者都免疫（行尾注释整体剥除后再逐字比对）。
- 片段头部的 `# path:La-Lb` 区间标注照旧（锚注是行级补充，不替代区间）。
- 已写章节回改时一并补齐（评审修复轮顺带）；新章 Write 站直接执行。

## 7. 收尾回指

每章末节（收尾前）：一段「L0 图点亮了哪块」+下一块预告（下一章 hook 的种子）。
终章（ch40）例外：全图点亮复盘。

## 8. 说人话（2026-08-16 用户定：「不要端着扯高大上的名词，放下姿态用正常的说法」+「说话要简单直接，以逻辑为主」）

- 用工程师之间正常说话的措辞写。判断标准：**这句话念出声，像不像一个懂行的人在给你讲**——不像就改。
- 禁端着的书面语/文绉绉名词：分野、擘画、赋能、抓手、纵深、护城河、打法、沉淀、拉通、颗粒度（粒度/精度之外的用法）、勾勒、底色（比喻义）等同类。
- **禁文艺比喻句**（2026-08-16 二次加严，用户抓「这套收敛的墓碑兼纪念碑，是 v0 双引擎的故居」）：
  - 每句话的**主语和指代必须一眼清楚指什么代码/机制/文件**——读者读完要能回答「这句话说的是哪个东西、它怎么了」；
  - 比喻预算：一个机制**至多一个短比喻**（且只在它真能点破理解时用），**绝不堆叠**（「墓碑兼纪念碑」「故居」连用=读者完全不知道指什么）；
  - 文学腔词黑名单：墓碑、纪念碑、故居、遗址、余晖、挽歌、落幕、谢幕、登场、尘封、活化石、丰碑、绝唱等；
  - 要表达「代码已删只剩空壳」这类事实，直接说事实：「v0 双引擎的代码已经删光，只剩这个空壳文件，内容只剩版权头」。
- **行话零假设**（2026-08-16 用户抓「墙上时钟的账」）：性能/系统行话（wall-clock、尾延迟、抖动等）首现也必须当场一句讲清——不确定读者懂不懂的词，就当不懂，写人话版（wall-clock→「实际花的时间」）。introduces 清单只登记大概念，行话靠这条兜。
- **OS 底座词零假设**（2026-08-28 加严，用户/真实读者抓 ch5 四连问：「共享内存为什么能跨进程」「零拷贝为何监控发完没」「用户态零拷贝啥意思、用户态内核态我也不懂」「oob consumer/provider 没介绍」）：OS/系统级底座词（用户态/内核态/系统调用/页表/虚拟地址/虚拟内存/物理内存/共享内存/mmap/进程隔离/零拷贝/socket 搬运语义/中断/上下文切换/NUMA/页锁定内存，清单不封顶）**首现必须当场讲清到「能说出它是什么、为什么在这里出现」**——一句不带解释的括注不算。写作团队反复高估读者的 OS 底座，这条按「读者没有操作系统方向的日常」执行。研究站对应产卡（researcher 契约已同步）。
- **比喻不越界**：「账本/对账」这类只在已立概念的语境里用（显存账本✓），不许延伸到别处（「对上图的账」「时钟的账」✗）。
- 「区分/区别/差异」不说「分野」；「细节程度」不说「颗粒度」；「积累」不说「沉淀」。发现同类新词照此办理。
- 该条同时是 reviewer 检查项（认知阶梯维⑦）+ **读者视角检查**（pipeline 读者 agent；2026-08-28 起由顾问性升级为门禁：术语首现未解释可 blocking）。
