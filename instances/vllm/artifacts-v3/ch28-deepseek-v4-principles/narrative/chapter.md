# 第 28 章　【primer】DeepSeek-V4 原理：七件套怎么还两本账

一百万个 token 的上下文，DeepSeek-V4-Pro 的单 token 算力只要 DeepSeek-V3.2 的 27%、KV cache 只要它的 10%。这 27% 是谁省出来的？不是一件事省的，是七件东西各还一部分：第一件把每 4 个 token 的缓存抹成 1 条，第二件在抹小了的这堆条目上打分、每个 query 只挑 512 条来看，第三件更狠，每 128 个 token 才留 1 条、而且一条不挑、全部看；第四件反着来，永远把最近 128 个 token 的**原样**缓存留着，是纯花销。第五件把残差从「加回去」改成 4 条流互相混合，还得用双随机矩阵把它管住；第六件 256 个专家挑 6 个，最前 3 层连挑都不挑，按 token id 查表派单；第七件顺手多预测一步，给投机解码当草稿。

问题跟着就来。压缩率 4 和 128 凭什么交替排布？缓存被抹成一条之后，query 怎么还能严格因果、还看得见最近那几个字？为什么压到 1/128 的层反而不需要选择器，压到 1/4 的层却非得有一个？残差扩成 4 条流，凭什么不把训练搞崩？这些问题的答案最后都落在两本账上：一本算每走一步要花多少算力（FLOPs 账），一本算每个 token 要占多少显存（KV cache 账）。本章把七件套逐件拆开，看清谁在还、还了多少、代价是什么。

这是 Part VI 的第三篇原理章（全书第四篇 primer）。上一章[第 27 章](../../ch27-quantization/narrative/chapter.md)把量化的格式账算清了：同一组数字换一把尺子记，字节数差一倍、误差被关在格里。本章算的是另一种账：这台模型的注意力与残差怎么把缓存的「条数」和「条宽」一起压下去。纸面数学在 v0.27.1 源码里的落点，每讲完一件就地钉一行；把这七件套装成一台能跑的机器（哪个类对应哪件、权重怎么流进去、几本 KV 账怎么分页）是紧接着的[第 29 章](../../ch29-deepseek-v4-assembly/narrative/chapter.md)的正题。

## 开账：三个数字，三个分母

先把靶子立起来。自回归解码的注意力每走一步都要把全部历史重读一遍（算力随序列长度平方增长，缓存随长度线性增长），1M 上下文把这两件事同时顶到墙上。DeepSeek-V4 摘要给了三个效率数字，引用它们最容易犯的错是把分母丢了：

- **V4-Pro 的单 token 推理 FLOPs 只要 V3.2 的 27%、KV cache 只要 V3.2 的 10%**：分子是 V4-Pro，分母是同为 1M 场景的 DeepSeek-V3.2（arXiv:2606.19348 摘要）。本章下面几笔逐层摊销按 V4-Flash 的 config 算，型号与口径都不同，别拿两者直接对账。
- **KV cache 可以降到约 2%**：这个分母不是 V3.2，而是「BF16 GQA8、head_dim 128」这一常见注意力配置基线（arXiv:2606.19348 §2.3.4 原句以它作 baseline）。写成「V4 的 KV cache 只有 2%」就是错误陈述。

三笔账各有归属。**FLOPs 账**由「压缩（条目数降 $`m`$ 倍）+ 稀疏（每个 query 实看条数封顶 $`k`$）+ 混合精度计算」三件一起还；**KV 体积账**由「条目数降 $`m`$ 倍 + 混合精度存储」还；而**滑窗是加账**，它每层额外多留 $`n_{\mathrm{win}}`$ 条未压缩的 KV，一件没省。

论文只给相对比例，不给绝对字节数，绝对量纲得自己按 config 与源码里的字节口径算。一条压缩条目由三段拼成：448 字节的 NoPE 段（走 FP8）、128 字节的 RoPE 段（保留 BF16 保位置精度）、8 字节的 FP8 缩放因子，合起来 584 字节；换算成「每 token 每层摊销多少字节」，就是拿 584 除以这一层的压缩率。逐层算完再按层数加权（43 层主干里前两层没有压缩机、中段 21 层压缩率 4、20 层压缩率 128）：

账立住了，先把机器的方框图画出来，之后每一节只是把它的一块放大了讲。

![一台 V4 的整机方框图：七件套分居六个位置（压缩两档共用一格）：注意力半层挂压缩、选择、保住近处三件，MoE 半层挂路由，残差带与主干出口各挂一件](../diagrams/ch28-fig-machine-map.png)

> *图注：本章的整机方框图（公式口径）。它就是[第 1 章](../../ch01-vllm-v1-in-one-map/narrative/chapter.md) L0 全图中间绿色「GPU 执行臂」列里模型层那一块的放大（图上右上角标着「本图的位置」），本章后面每一张机制图都是这张图上某一件的内部放大；同一台机器的代码口径（哪个类、哪个字段对应哪件）留给[第 29 章](../../ch29-deepseek-v4-assembly/narrative/chapter.md)。竖着读是一个 token 的路：入口把隐状态复制成 4 条流（`hc_mult = 4`），穿过 43 个「一个注意力半层加一个 MoE 半层」的层对，出口把 4 条流展平，先把一份拷给多预测一步、再用 `hc_head` 的 sigmoid 门控压回 1 条，最后归一化、算 logits。横着读是七件套分居六个位置（压缩缓存那一格同时挂着第一件与第三件，就是同一台压缩机的 4 与 128 两个档位）：注意力半层挂三件：压缩缓存（第 3 层起每 4 或每 128 个 token 一条、逐层交替；第 1–2 层是牌子 0，没有压缩机、只有滑窗）、选择器（只站在牌子 4 的层上、挑 512 条）、滑窗带（恒长 128 条原样 KV）；MoE 半层挂一件（256 挑 6 加 1 个共享专家，最前 3 层改按 token id 查表）；残差带（4 条流，每半层一次读入加一次写回）与主干出口的分叉各挂一件。左下角那条小图把「一次注意力实际看到什么」按比例画出来：CSA 层 128 条滑窗加 512 条压缩条目得 640 条，HCA 层 128 加 7812 得 7940 条，压得少的挑着看、压得狠的一条不挑全看，条长的差距在图上直接看得见。*

一台 V4 主干是 43 个结构相同的「半层对」串起来：一个注意力半层加一个 MoE 半层，外面套着一条**四条流的残差带**（第五件）。每进一个半层，先从这条带里把四条流按学习出来的权重聚成一路（读入），把这一路交给子层去算（注意力半层算注意力，MoE 半层算专家），算完的结果再按学习出来的权重散回四条流、与混合过的旧残差相加（写回）。主干末端，四条流先摊平拷一份交给「多预测一步」的模块（第七件），然后压回一条、做最后一层归一化、算 logits。

注意力半层里有三样东西同时挂着。第一样是**一份压缩缓存**：历史每 $`m`$ 个 token 被抹成一条条目，$`m`$ 逐层交替取 4 或 128（第一件与第三件，是同一台压缩机的两个档位，论文里叫 CSA 与 HCA）。第二样是一条**滑窗带**，永远保留最近 128 个 token 的原样 KV，不压缩（第四件）。第三样只在 $`m=4`$ 的层上多出来：**一只选择器**（第二件），它给每个压缩条目打分，挑出 512 条，与滑窗那 128 条拼在一起，交给核心注意力去看：它因此不必读全部历史，只读这六百多条（512 加 128）。$`m=128`$ 的层没有选择器：条目本来就少，全看不比挑选贵。

一个 token 在 MoE 半层里还会被路由一次：256 个专家里挑 6 个算，另有 1 个共享专家无条件算（第 1 个半层起就有）；最前 3 层的挑选方式不一样，不按分数挑，直接按 token id 查表（第六件）。

这就是全章的地图：**账算在「条数」与「条宽」上，机制就落在「压缩」「选择」「保住近处」三件事上，残差与路由是搭台子的。** 下面七节按这个顺序展开，最后用一张对账表收口。

## 第一件：压缩，$`2m`$ 个位置软池化成 1 条

卷积网络里的最大池化是在 2×2 个格子里挑一个最大的走；这里换成加权平均版：$`2m`$ 个位置各算一个分数，softmax 把分数变成加起来等于 1 的份额，再按份额把这 $`2m`$ 个向量逐元素加权求和成 1 条。它**不是摘要**：没有生成器、没有语言模型，只有两组投影、一次 softmax、一次加权和；「挑人」的能力全在学出来的权重里。

公式分两拍。第一拍，两组投影各出一份 KV 原料和一份权重原料（arXiv:2606.19348 §2.3.1 Eq.(9) 与 Eq.(10)）：

```math
C^a = H \cdot W^{aKV}, \qquad C^b = H \cdot W^{bKV}
```

```math
Z^a = H \cdot W^{aZ}, \qquad Z^b = H \cdot W^{bZ}
```

四组矩阵都是 $`d\times c`$ 的可训练参数。为什么是两组而不是一组：第 $`i`$ 条条目要同时吃「自己这一段 $`m`$ 个 token」和「前一段 $`m`$ 个 token」，$`a`$ 组负责当前窗，$`b`$ 组负责前一个窗，两半区靠重叠让块边界上的信息被平滑而不是被切断。

![一条 hidden 变出四组投影：两组喂混合、两组决定怎么混合，a 半区当前窗、b 半区前一个窗](../diagrams/ch28-fig-csa-projections.png)

> *图注：一条 $`H`$ 分出四条投影：实底的 $`C^a,C^b`$ 是**要被混合**的向量、虚线的 $`Z^a,Z^b`$ 是**决定怎么混合**的分数原料（还不是权重，要过 softmax 才是）。a/b 两组对齐的是两个窗：第 $`i=1`$ 条条目从 $`a`$ 半边取行 [4, 5, 6, 7]（当前窗）、从 $`b`$ 半边取行 [0, 1, 2, 3]（前一个窗），而 [0, 1, 2, 3] 正是第 $`i=0`$ 条取过的那 4 行：两个窗在这里叠了起来。四组缺一不可，少一组就没有「窗」可叠。中间那四个投影块上标着形状 $`(16, 2)`$（玩具口径 $`d=3`$、$`c=2`$、$`n=16`$），底部给出 token 4 的四个投影值：$`C^a`$ 是 [0.5, 1.5]、$`C^b`$ 是 [1.0, 0.5]、$`Z^a`$ 是 [0.5, 1.0]、$`Z^b`$ 是 [1.5, 0.5]。v0.27.1 把四组权重压成一条 GEMM（一次大矩阵乘、四组输出一起算）一枪出（系数 `coff = 1 + overlap` 取 2），那只是打包，读式子时按四组读。*

第二拍是归一与加权求和（Eq.(11) 与 Eq.(12)）。先给两半区各加上一个可学习的位置偏置 $`B^a,B^b\in\mathbb{R}^{m\times c}`$（它让「窗内第几个位置」也参与权重，即权重不只是内容相关、还带位置先验），把两半区竖着叠成 $`2m`$ 行做一次行方向 softmax，然后用这些权重把 KV 原料逐元素加权求和：

```math
[S^a_{mi:m(i+1)-1}; S^b_{m(i-1):mi-1}] = \mathrm{Softmax}_{\mathrm{row}}\left([Z^a_{mi:m(i+1)-1} + B^a;\, Z^b_{m(i-1):mi-1} + B^b]\right)
```

```math
C^{\mathrm{Comp}}_i = \sum_{j=mi}^{m(i+1)-1} S^a_j \odot C^a_j + \sum_{j=m(i-1)}^{mi-1} S^b_j \odot C^b_j
```

![四档实现阶梯：摘掉位置偏置就退化成算术平均，每补一件输出就位移一次](../diagrams/ch28-fig-csa-ladder.png)

> *图注：同一组输入走四档，每加一件东西输出就位移一次。sec1 什么机制都没有（窗内分数相同、也没有输入相关的投影）：softmax 在等分分数上退化成等权平均，四格权重都是 0.25、输出 [4.0, 6.0] 恰好就是算术平均；sec2 加上位置偏置 $`B^a`$（取 [0.5, 0.4, 0.3, 0.2]，行 = 窗内第几格），权重变成等高的反面 0.288651、0.261183、0.236328、0.213838，输出 [3.750706, 5.750706]（位移 0.249294）；sec3 让分数改由输入投影出来（这一档只看内容投影 $`Z`$，位置偏置 $`B`$ 已在前一档演示过，输出 [3.135686, 6.969646]，位移 1.218941）；sec4 才是完整版：窗宽从 $`m`$ 拉到 $`2m`$、两半区跨 8 个元素做一次 softmax（输出 [0.576481, 0.469171]，位移 6.500476，权重逐列和 1.0）。这张图要带走的一句话是 **$`B`$ 是「窗内第几格」唯一的信号源**：窗内两个内容相同的格子，没有 $`B`$ 就没有任何东西能把它们区分开；而 sec4 之所以叫「完整」，是因为归一范围变了——softmax 跨的是 8 个元素而不是 4 个，这个跨度正是重叠窗的配套写法。压缩率之所以恰好是 $`1/m`$ 而不是 $`1/2m`$，靠的是下节要推的重叠本身（相邻条目共享 $`m`$ 个输入，每新增一条只消耗 $`m`$ 个新 token），不是归一范围。*

三处读法要当场钉住。**其一，归一范围是 $`2m`$ 个元素**，不是 $`m`$：softmax 跨 `[Z^a 当前窗; Z^b 前窗]` 这 $`2m`$ 行逐列归一，所以每个位置的权重是「在这 $`2m`$ 个候选里占多少」。**其二，$`C^{\mathrm{Comp}}_i`$ 由 $`2m`$ 个 KV 条目贡献，但产出条数只有 $`n/m`$**：第 $`i`$ 条用的 $`C^b`$ 下标，正是第 $`i-1`$ 条用的 $`C^a`$ 下标，相邻条目共享一半输入，所以每新增一条只消耗 $`m`$ 个新 token。**其三，$`i=0`$ 是唯一特例**：越界的 $`Z^b`$ 填负无穷、$`C^b`$ 填 0，于是第一个窗只看自己。

先看一个小例子把「软池化」的脾气摸清（$`m=4`$、$`c=2`$，8 个 $`(Z+B)`$ 分数配 8 个 KV 值）：

一个直接的推论：$`C^{\mathrm{Comp}}`$ 的每个分量都是同一列输入的凸组合（权重逐列和为 1、非负），所以它逐元素不放大——第 $`c`$ 个分量的绝对值不超过所有输入 $`C_j`$ 第 $`c`$ 个分量绝对值的最大值。这里要小心界成立的范围：逐元素的那条（$`L_\infty`$ 口径）成立，换成 2-范数就不成立，因为各列的权重互相独立、没有这条保证。

### 两扇窗叠着推：为什么恰好压到四分之一

「每 $`m`$ 个 token 压成 1 条」这句话里藏着一个容易读漏的细节：$`2m`$ 个输入对应 1 条产出，但产出条数是 $`n/m`$，不是 $`n/2m`$。把 12 个 token 的归属列出来就清楚了：

### 落点：一个开关两件事，位置偏置写在状态里

v0.27.1 里压缩机的构造只有几行，两处特别值钱：

**伪码：CSA 压缩（config 口径 $`m=4`$、$`c=512`$、窗宽 $`2m=8`$）**

```python
def csa_compress(H, W_aKV, W_bKV, W_aZ, W_bZ, B, m):
    n = H.shape[0]
    C_a, C_b = H @ W_aKV, H @ W_bKV      # Eq.(9)  各 [n, c]
    Z_a, Z_b = H @ W_aZ,  H @ W_bZ       # Eq.(10) 各 [n, c]
    B_b, B_a = B[:, :c], B[:, c:]         # 本仓 ape 的列序是 [前窗; 当前窗] = [B^b; B^a]，与论文的 [B^a; B^b] 相反（见上面「标签陷阱」）
    out = []
    for i in range(n // m):
        cur = Z_a[i*m:(i+1)*m] + B_a                      # 当前窗 m 个
        prv = Z_b[(i-1)*m:i*m] + B_b if i > 0 else full((m, c), -inf)
        S = softmax(concat([cur, prv], axis=0), axis=0)   # Eq.(11) 跨 2m 归一
        entry = (S[:m] * C_a[i*m:(i+1)*m]).sum(axis=0)    # 两片都是 (m, c)
        if i > 0:                                         # i=0 时 S[m:] 恒为 0
            entry = entry + (S[m:] * C_b[(i-1)*m:i*m]).sum(axis=0)   # Eq.(12)
        out.append(entry)
    return stack(out)                    # [n // m, c]
```

这段伪码钉住三个不变量：归一方向是**跨 $`2m`$ 行逐列**（不是跨 $`c`$ 列）；越界半区以负无穷与 0 参与，因此第一个窗只看自己（$`i=0`$ 时 $`S[m:]`$ 恒为 0，少加那一项不改变结果）；产出条数恰好 $`n/m`$。

## 第二件：选择，在压缩块上打分，只挑 $`k`$ 条

压缩把候选从 $`n`$ 个 token 变成 $`n/m`$ 个块，但 1M 上下文下 $`n/m`$ 仍有 25 万条。全部看不行，于是请一位便宜的初筛员（就是前面方框图里那只「选择器」，实现里叫 indexer，开账表里那条 132 B 的小头缓存归它）：它给每个块打一个分，只把分数最高的 $`k`$ 条交上去。这位初筛员不是新发明的，DeepSeek-V3.2 的 lightning indexer 就在做这件事（arXiv:2512.02556 §2.1 Eq.(1)(2)），V4 只把打分对象从「每个 token 的键」换成「每个压缩块」（[第 26 章](../../ch26-deepseek-indexer-nsa-dsa/narrative/chapter.md)讲过那套打分算子与它自己那本缓存账，这里只讲公式）。

![一次降维两处用：索引器搭在主注意力本来就有的低秩瓶颈上](../diagrams/ch28-fig-latent-fork.png)

> *图注：整条低秩瓶颈只有一次降维：hidden 先压成潜向量 $`c^Q`$，再由它分出两个 q：左边那个给「选谁」的索引器（config 口径 $`n_h^I\times c^I = 64\times128`$），右边那个给「算什么」的主注意力（$`n_h\times c = n_h\times512`$）。所以索引器不是另起的投影链：它搭在主注意力本来就有的低秩瓶颈上，多花的只有一份小头缓存，不多一条降维。它的头维只有 128（主注意力是 512），便宜也正便宜在这里。读法是「同一条链的两个出口」，不是两条并排的链。玩具缩放（$`n_h^I=2`$、$`c^I=2`$、$`n_h=2`$、$`c=4`$）给出的 q 形状 $`(2,4)`$、kv 形状 $`(3,4)`$ 与每行和为 1 的注意力权重，下一张打分图就接着这组数走。*

打分要三样东西。**低秩的 q**：先把 hidden 压到潜空间，再从潜空间铺成索引器的多头查询（V4 报告 §2.3.1 Eq.(13)(14)）：

```math
\mathbf{c}_t^Q = \mathbf{h}_t \cdot W^{DQ}
```

```math
[\mathbf{q}_{t,1}^I; \dots; \mathbf{q}_{t,n_h^I}^I] = \mathbf{q}_t^I = \mathbf{c}_t^Q \cdot W^{IUQ}
```

**逐头的标量权重**：每个索引头投一票，票的分量是学出来的一个标量（V4 报告 §2.3.1 Eq.(15)）：

```math
[w_{t,1}^I; \dots; w_{t,n_h^I}^I] = \mathbf{w}_t^I = \mathbf{h}_t \cdot W^w
```

**打分与选择**：每个头对每个块做一次内积、过 ReLU、按各自的票权加权求和，取 top-$`k`$（V4 报告 §2.3.1 Eq.(16)(17)）：

```math
I_{t,s} = \sum_{h=1}^{n_h^I} w_{t,h}^I \cdot \mathrm{ReLU}\left(\mathbf{q}^I_{t,h} \cdot K^{\mathrm{IComp}}_s\right)
```

```math
\mathcal{C}_t^{\mathrm{SprsComp}} = \left\{C^{\mathrm{Comp}}_s \mid I_{t,s} \in \mathrm{Top}\mathrm{-}k(I_{t,:})\right\}
```

两处设计要点。**ReLU 是纪律**：负相关的头不会给块扣分，分数只被正相关推动；去掉它，64 个头在 25 万个候选上的负分会累积，靠「多数头反对」把某个块压到很负的位置（小例子里单块会拿到 −0.95，加了 ReLU 是 0）。**$`\mathbf{c}_t^Q`$ 是共享的**：同一份低秩潜向量分两路，一路接索引器的 $`\mathbf{q}^I`$（$`W^{IUQ}`$，铺成 64 头乘 128 维），另一路接主注意力的 $`\mathbf{q}`$（$`W^{UQ}`$，铺成 $`n_h`$ 头乘 512 维），一次降维两处用，这条线索在「共享 KV 的 MQA」那一节兑现。

先看 2 个索引头、4 个候选块的玩具表：

### 候选墙本身就是因果的：为什么不需要掩码表

因果在稀疏注意力里通常靠一张掩码表（把未来位置的分数打成负无穷）。这套机制不需要：候选集合只由「已经攒满的块」组成。第 $`t`$ 个 query 能看到的块号上界是它前面所有完整块的数量：

<!-- trace: ch28-m06 -->
| 步骤 | 动作 | 关键数值 | 判定 |
|---|---|---|---|
| t=0 到 t=2 | 候选数 = 已完成的块数 | 论文口径 0 / 0 / 0；代码口径 0 / 0 / 0，可见块为空 | 还没攒满一块：t=2 时一个压缩条目都看不到 |
| t=3（块尾） | 两种口径第一次分叉 | 论文 3 除以 4 得 0；代码 (3+1) 除以 4 得 1，可见块 [0]，差一格 | 代码允许块尾看自己那块——仍严格因果（不含未来 token） |
| t=7、t=11（块尾） | 同样的差一格 | 论文 1 对代码 2；论文 2 对代码 3 | 差一格只出现在块尾 token（t 取 3、7、11） |
| 因果进入 top-k | toy 复用同一份分数表演示排序：墙外的块号记作 −∞，表示**不在候选集**（实现里这些号根本不会进缓冲，见下段的 −1 哨兵填充） | 阈值取 8、topk 取 2 时选 [7, 4]；阈值取 6 时选 [4, 1] | 只看已完成的块，排序才算得对 |
| 候选不足 | 候选 2 个而 topk 取 5 | 缓冲 = [0, 1, -1, -1, -1]（全选路径按序填号，不排序） | 短上下文里「全选」与「−1 哨兵」是同一件事的两面 |

值得注意的是论文口径与代码口径**差一格**：论文写 $`s<\mathrm{Floor}(t/m)`$（只能选严格在自己所在块之前的完整块），实现统一用 `(position + 1) // compress_ratio`（已完成的块数，见 `vllm/models/deepseek_v4/attention.py:L72-L88` 与 `vllm/models/deepseek_v4/sparse_mla.py:L374-L419` 两处同口径）。差的那格是**当前块**：块尾 token 能看自己刚产出的那一块。它仍然严格因果（不含未来 token），因为条目里只有已经处理过的 token。正文按论文给公式、讲代码时按代码口径陈述，两者不必强行说成等价：论文 §2.3.3 那句「访问不到自己压缩块内其它 token 的信息」是按「块尾 query 看不到自己那一块」的字面读法写的，代码在这一格上确实放宽了一格；放宽的那一份不破坏因果（条目里只有已经处理过的 token），也给不出块内逐 token 的粒度——两边真正一致的只是「块内没有逐 token 粒度」这层实质。

![候选墙：因果由候选集合本身保证，不需要掩码表](../diagrams/ch28-fig-candidate-wall.png)

> *图注：逐 token 列一遍就看清了：$`t=0,1,2`$ 时可见压缩块是 **0 个**（一块都没攒满，这几个 token 的全部上下文只有滑窗里那 1、2、3 条），$`t=3`$ 才有第 0 块，之后墙随 $`t`$ 线性长，1M 下长到 250000 条、靠 top-$`k`$ 封在 512 条。论文口径 $`s<\mathrm{floor}(t/m)`$ 与代码口径 $`(t+1)//m`$ 只在块尾 token（$`t=3,7,11`$）上差一格，差的是「自己刚产出的那一块」——它装的全是已经算过的 token，不含未来 token，所以仍严格因果，但论文那句「访问不到自己压缩块内其它 token 的信息」的字面限定确实被放宽了一格。这两种口径别写成「等价」，写「定义域差一格」。*

短上下文还有一条快路径：候选数不超过 $`k`$ 时排序没有意义，直接全选，本仓的做法是把 `0..num_compressed-1` 全写进缓冲、其余填 −1 哨兵：

```python
# vllm/models/deepseek_v4/attention.py:L71-L87 · _fill_short_context_topk_indices
@triton.jit
def _fill_short_context_topk_indices(
    output,
    positions,
    TOP_K: tl.constexpr,
    COMPRESS_RATIO: tl.constexpr,
    PADDED_TOP_K: tl.constexpr,
):
    # small triton kernel that selects every candidate, -1 otherwise
    row = tl.program_id(0)
    offsets = tl.arange(0, PADDED_TOP_K)
    num_compressed = (tl.load(positions + row) + 1) // COMPRESS_RATIO
    tl.store(
        output + row * TOP_K + offsets,
        tl.where(offsets < num_compressed, offsets, -1),
        mask=offsets < TOP_K,
    )
```

索引器自己那条短路在最外面：


**伪码：索引器打分与选块（sec1 基础 → sec2 完整）**

```python
def indexer_select_sec1(cand):            # sec1 基础：候选不超 k，全选
    return cand                           # 一个分数都不比（短上下文走这条，缓存照建）

def indexer_select(h_t, K_IComp, c_Q, W_IUQ, W_w, m, k, position):   # sec2 完整
    q_I = c_Q @ W_IUQ                     # Eq.(14) [n_h_I, c_I]，c_Q 与主注意力共享
    w_I = h_t @ W_w                       # Eq.(15) [n_h_I]
    cand = arange(0, (position + 1) // m) # 候选 = 已完成的块（代码口径）

    return cand[topk_indices(I, k)]       # Eq.(17)
```

实现里这两档是同一个函数的两条分支（上面那段快路径源码），短上下文走 sec1、长上下文走 sec2。它钉住的不变量是「候选集合本身就是因果的」：不需要掩码表，也不需要负无穷把未来位置打掉。

## 收尾件：共享 KV 的 MQA，与那份一次降维两处用的潜向量

选完条目，注意力本身反而最简单。每条压缩条目**同时当 key 和 value**，而 query 是多头的（V4 报告 §2.3.1 Eq.(18)(19)）：

```math
[\mathbf{q}_{t,1}; \dots; \mathbf{q}_{t,n_h}] = \mathbf{q}_t = \mathbf{c}_t^Q \cdot W^{UQ}
```

```math
\mathbf{o}_{t,i} = \mathrm{CoreAttn}\left(\mathrm{query} = \mathbf{q}_{t,i},\ \mathrm{key} = \mathcal{C}_t^{\mathrm{SprsComp}},\ \mathrm{value} = \mathcal{C}_t^{\mathrm{SprsComp}}\right)
```

「共享 KV」这四个字不是省显存的工程技巧，而是「压到最后只剩一条向量」的必然后果：一条 $`c`$ 维条目想不当 K/V 都难，头数只能加在 query 那一侧。[第 24 章](../../ch24-primer-attn-variants/narrative/chapter.md)讲过 MQA 是「所有头共用一份 K/V」的极端档，这里的区别在于那份 K/V 不是「从每个 token 投影出来再共享」，而是**根本就不存在逐 token 的 K/V**——历史只剩条目。

四行读数把这段的形状钉死：

<!-- trace: ch28-m07 -->
| 步骤 | 动作 | 关键数值 | 判定 |
|---|---|---|---|
| 打分 | 核心注意力：输出等于权重乘 kv（同一张量既当 K 又当 V） | 权重（2 头乘 3 条）= [[0.465836, 0.362793, 0.171371], [0.307196, 0.186324, 0.50648]]，每行和 = [1.0, 1.0] | kv 轴上没有 head 维（形状 (3, 4) 而不是 2×3×4） |
| 输出 | 没有第二份 value 投影 | o = [[0.647232, 1.103042, 0.828629, 0.705536], [0.400358, 1.120872, 0.49352, 1.199285]] | 一行矩阵乘完事 |
| 共享性验证 | 把 kv[0] 加 1.0 | 2 个头**同时**变：变化量 = [0.860147, 1.102083, 0.779502, 0.389647, 0.753717, 0.850275, 0.721531, 0.132214] | 没有哪一头能绕过它 |
| 潜向量复用 | 同一份低秩潜向量分叉两路 q | 索引器 q：64 乘 128；主注意力 q：n_h 乘 512 | 一次降维两处用（Eq.13 与 Eq.18 同一个 $`c^Q`$） |

第三行是这段的判据：动一条条目，两个头的输出**一起**变，这就是 MQA 与 MHA 的分水岭（MHA 里每个头有自己的 K/V，动一份动不了另一份）。

官方参考实现里「共享」是最字面的一行：`sparse_attn(q, kv, ...)` 只传**一份** kv，核里同一个张量既进 key 的矩阵乘也进 value 的矩阵乘（官方参考实现（DeepSeek-V4-Pro inference/kernel.py:L295-L299、L328、L343））；主注意力的 q 与索引器的 q 也确实来自同一个张量（同包 inference/model.py:L496 的 `qr = q = self.q_norm(self.wq_a(x))` 传给 L411 的 `q = self.wq_b(qr)`；这里 `wq_a` 就是 Eq.(13) 的降维矩阵 $`W^{DQ}`$、`wq_b` 是 Eq.(18) 的升维矩阵 $`W^{UQ}`$，中间的 `qr` 就是那份共享的潜向量 $`c^Q_t`$）。

**伪码：核心注意力（共享 KV 的 MQA）**

```python
def core_attn(q, entries):          # q: [n_h, c] 诸头；entries: [L, c]
    w = softmax((q @ entries.T) * c ** -0.5, axis=-1)   # Eq.(19)
    return w @ entries              # key 与 value 是同一张 entries
```

它钉住的不变量是「KV 轴上没有头维」：输出的头数只由 q 决定，条目侧一份张量服务所有头。

## 第三件：HCA，压得更狠，一条不挑

同一台压缩机换一个档位：窗口从 $`2m=8`$ 拉到 $`m'=128`$，丢掉重叠（只剩一组 $`C/Z`$），也丢掉选择器。公式与 CSA 同构（arXiv:2606.19348 §2.3.2 Eq.(20)-(26)）：

```math
C = H \cdot W^{KV}, \qquad Z = H \cdot W^{Z}
```

```math
S_{m'i:m'(i+1)-1} = \mathrm{Softmax}_{\mathrm{row}}\left(Z_{m'i:m'(i+1)-1} + B\right)
```

```math
C^{\mathrm{Comp}}_i = \sum_{j=m'i}^{m'(i+1)-1} S_j \odot C_j
```

核心注意力与 CSA 完全同构（Eq.(24)-(26) 与 Eq.(18)(19) 逐项对应；其中 Eq.(24) 那条 $`\mathbf{c}_t^Q`$ 的降维式与 Eq.(13) 同形，两档共用同一次降维），唯一的区别是 key 与 value 是**整份** $`C^{\mathrm{Comp}}`$，不是 top-$`k`$ 子集。把两组公式并排看，三处差别一目了然：只有一组 $`C/Z`$（没有 a/b 两半、没有重叠窗）、窗宽是 $`m'`$ 而不是 $`2m`$、**没有索引器**。

还有一件两档共用的收尾件，论文落在 §2.3.2 的尾句上：核心注意力的输出不是直接当结果用，而是先把 $`g`$ 个组的中间输出拼起来（$`d_g g`$ 维）、再投一次到 $`d`$ 维得到 $`\hat o_t`$（分组输出投影）。这里的「组」是**头的分组**：把 $`n_h`$ 个 query 头分成 $`g`$ 组（config 口径 `o_groups=8`，即 $`g=8`$），每组经一次低秩投影压到 $`d_g`$ 维（config 口径 `o_lora_rank=1024`），拼成 $`d_g\cdot g`$ 维后再投回 $`d`$ 维（官方参考实现里 `o_groups`/`o_lora_rank` 就是两个模型超参，字段名与 config 的键同名；官方参考实现（DeepSeek-V4-Pro inference/model.py:L450、L462-L463、L537-L542））。这就是后面反旋那一节要说的那族输出投影（代码里的 `wo_a`/`wo_b`），反旋必须发生在它之前。CSA 侧论文没有单列这一式，实现里两档走的是同一段收尾，这也是「两档同构」的一部分。

![两档压缩机并排：CSA 两组投影加索引器挑 512 条，HCA 一组投影、一条不挑全看](../diagrams/ch28-fig-csa-vs-hca.png)

```python
def hca_compress(H, W_KV, W_Z, B, m_prime):
    C, Z = H @ W_KV, H @ W_Z                    # 一组投影，没有 a/b
    n_entry = H.shape[0] // m_prime
    out = []
    for i in range(n_entry):
        blk = slice(i*m_prime, (i+1)*m_prime)
        S = softmax(Z[blk] + B, axis=0)         # 归一范围就是 m'，没有重叠
        out.append((S * C[blk]).sum(axis=0))    # Eq.(23)
    return stack(out)

def hca_attend(q, entries, position, m_prime):
    cand = entries[: (position + 1) // m_prime] # 候选 = 全部已完成的块
    return core_attn(q, cand)                  # Eq.(26)：一条不挑
```

它钉住的是「这一档没有选择器」：候选集合、压缩方式、核心注意力三处的代码路径都不需要打分与排序。

## 第四件：滑窗，唯一只花不省的一件

压缩把分辨率换成了条数，代价在两处：块级粒度看不见块内先后（query 只能整块地看，同一块里更早的 token 在块级表达不出来），以及最近的 token 要么在还没攒满的块里、要么刚被抹进一个混了 $`m'`$ 个 token 的条目里。语言建模里最近的 token 通常最该被精确看到，于是 V4 反手加一件：每层额外产出 $`n_{\mathrm{win}}`$ 条**未压缩**的 KV，对应最近 $`n_{\mathrm{win}}`$ 个 token，与压缩条目一起送进同一次注意力（arXiv:2606.19348 §2.3.3）。

这一件在账上是纯花销，但它换来两样东西。第一样是**保真**：近处的字以原样参与打分，不被任何池化抹平。第二样是**看得见未完成的部分**：压缩机每 $`m`$ 个 token 才产出一条，解码时最新那几个不满一块的 token 还没有压缩条目，只有滑窗看得见它们的原样 KV。[第 26 章](../../ch26-deepseek-indexer-nsa-dsa/narrative/chapter.md)那个「位置 3 只攒出 1 个压缩块」的例子，说的就是这条时间差。这一条是**实现层口径**（论文只写了前两条：严格因果与近处更相关），分层标清楚，别把它读成论文结论。

## 位置与分母：两个容易漏掉的小件

### 只转最后 64 维，输出侧还要转回来

RoPE（旋转位置编码）在这套注意力里只作用在**最后 64 维**上，前面的 448 维是 NoPE（不带位置）。这两条都是论文明写的（arXiv:2606.19348 §2.3.3 原句：we also apply RoPE with position $`-i`$ on the last 64 dimensions of each $`o_{t,i}`$），不是纯实现细节，所以锚给到节号。这一点论文与两侧实现四处一致：query、滑窗的 KV、压缩条目都只对最后 64 维做旋转（本仓 `vllm/models/deepseek_v4/compressor.py:L403-L406` 与 `fused_inv_rope_fp8_quant.py` 的核都以这个分界切段；官方参考实现（DeepSeek-V4-Pro inference/model.py:L499、L504、L367）三处都是 `[..., -rd:]`）。

更细的一处是输出侧：核心注意力的输出还要反向旋转一次（论文原句写的就是 position $`-i`$）。先说记号：论文这里的 $`i`$ 与它自己 Eq.(19) 里 $`o_{t,i}`$ 的头号 $`i`$ 同名，而我们手里只有这一句原句、没有它的前后文，所以本章不替它裁定这个 $`i`$ 指什么；两侧实现做的是同一件事：反旋传入的不是条目的位置，而是 **query 自己的位置**。官方参考实现（DeepSeek-V4-Pro inference/model.py:L486、L534）取 `freqs_cis[start_pos:start_pos+seqlen]` 再置 inverse 标志；本仓的核里 `pos = tl.load(positions_ptr + pid_token)`（`vllm/models/deepseek_v4/common/ops/fused_inv_rope_fp8_quant.py:L92`）。

为什么非转不可，链条是一环扣一环的：压缩条目写入时带的是**块级位置**（一条条目代表整块，位置取块起点，代码注释原话是 `(positions // compress_ratio) * compress_ratio`，`vllm/models/deepseek_v4/compressor.py:L403`），query 带的是自己的位置 $`t`$，两者差着一整个块的相位；核心注意力的输出是条目向量的加权和，继承的是条目那套相位，而它下一步要进的输出投影（`wo_a`/`wo_b` 那一族升维与混合矩阵）是按位置无关设计的，所以在投影之前必须先把这套相位解掉，用的就是 query 自己的位置（`vllm/models/deepseek_v4/attention.py:L396` 那行 `self._o_proj(o, positions)`）。解完之后每条条目留下的相位差是（条目位置 − query 位置），正是这一段注意力该携带的相对距离。

反向旋转就是正向旋转的逆运算，两个方向的公式只差 partner 项的一个符号：

<!-- trace: ch28-m10 -->
| 步骤 | 动作 | 关键数值 | 判定 |
|---|---|---|---|
| 频率表 | 频率 = 底数的负 2j/rope_dim 次方，j 取 0 到 1 | [1.0, 0.01] | 两个频率都可手算 |
| 正向旋转 | 偶数位乘 cos 减 partner 乘 sin，奇数位乘 cos 加 partner 乘 sin | cos = [-0.989992, 0.99955]、sin = [0.14112, 0.029996]，转出 [9.0, 9.0, -1.272233, -1.838865, 2.878668, 4.088187] | 前 2 维（NoPE 段）纹丝不动 |

纸面推导是一行三角恒等式：正向变换是旋转矩阵 $`R(\theta)`$，反向用 $`R(-\theta)`$，两者的乘积是恒等矩阵（二维旋转的封闭性，加上 $`\cos^2+\sin^2=1`$）。所以「转过去再转回来」逐位复原，NoPE 段两次都原样。

![正反两次旋转只差 partner 项的一个符号，转回来逐位复原](../diagrams/ch28-fig-inv-rope.png)

> *图注：一对维度 $`[1.0, 2.0]`$ 正向转到 $`[-1.272233, -1.838865]`$，反向再转逐位回到 $`[1.0, 2.0]`$（max|差| = 0.00000000）；两个方向的式子只差 partner 项的符号：正向偶数位是减、反向是加，其余逐字相同。前面 448 维是 NoPE 段，两次旋转都不参与（$`[9.0, 9.0]`$ 原样），转的只有最后 64 维。为什么要转回来在图的下半左边那张卡：压缩条目带的是**块级位置**（$`m=4`$ 时前 3 条只有 [0, 4, 8] 三个值），query 带的是自己的位置（0..11 十二个值），两个口径对不上；输出继承的是条目那套相位，所以在进输出投影之前，要按 query 自己的位置把它解掉。*

**伪码：输出侧反向旋转（只动最后 64 维）**

```python
def inv_rope(o, positions, cos_sin_cache, rope_start):
    # positions = query 自己的位置（不是条目的块级位置）
    x = o[..., rope_start:]                     # 只取最后 64 维
    partner = x[..., reversed_pairs]            # 相邻两维互换（xor 1）
    cos, sin = cos_sin_cache[positions]
    even = x * cos + partner * sin              # 与正向反号
    odd  = x * cos - partner * sin
    o[..., rope_start:] = interleave(even, odd) # 448 维 NoPE 段不动
    return o
```

它钉住的不变量是「反旋与正旋互为逆」：每一对维度转过去再转回来必须逐位复原（实测最大偏差 0.00000000），否则条目携带的块级位置会污染 query 的位置口径。本仓这条在 `vllm/models/deepseek_v4/common/ops/fused_inv_rope_fp8_quant.py:L85-L107` 核里，`x_add = x * cos + partner * sin` 与 `x_sub = x * cos - partner * sin` 同核接到 FP8 量化；官方参考实现用共轭复数实现同一件事（inverse 标志位加上 `freqs_cis.conj()`，官方参考实现（DeepSeek-V4-Pro inference/model.py:L235-L237、L534））。

### sink：给每个头一个「不看」的权利

最后一个分母上的小件。[第 26 章](../../ch26-deepseek-indexer-nsa-dsa/narrative/chapter.md)的装配段已经点过 `attn_sink` 这个参数（「每头一个可学习标量，指数加进 softmax 分母、充当吸收富余注意力的虚拟出口」），这个现象本身在[第 21 章](../../ch21-attention-backends/narrative/chapter.md)交代过，这里补的是它的公式出处与数值行为。标准 softmax 强制所有可见位置的权重和等于 1：哪怕当前 query 跟看见的内容都关系不大，它也只能把 1 分出去。V4 在 HCA 层加了一个可学习的 sink logit $`z'_h`$，它的指数项**只加进 softmax 的分母**，分子里没有对应的 value（arXiv:2606.19348 §2.3.3 原话是「$`\exp(z'_h)`$ 会被加进注意力分数的分母」，让每个 query 头能把总注意力质量调成不等于 1、甚至接近 0）。

<!-- trace: ch28-m11 -->

| 基例 sink 取 None | 退化成普通 softmax | 权重 = [0.731059, 0.268941]、总质量 = 1.0 | 负无穷的指数是 0，等于没有 sink |
| sink 取 1.5 | 只改分母 | 权重 = [0.50648, 0.186324]、总质量 = 0.692804 | 相对比例不变、绝对份额整体缩水 |

写成显式式子，这条性质一眼可见。对 logits $`\{z_j\}`$ 与 sink $`z'`$，权重是

```math
w_j = \frac{\exp(z_j - m)}{\sum_j \exp(z_j - m) + \exp(z' - m)}
```

其中 $`m`$ 是 logits 与 sink 里的最大值（分母里逐项减去它不改变比值；这个 $`m`$ 只是本节的 max-logit 记法，与前面那个压缩率 $`m`$ 无关）。于是权重和 $`S/(S+\exp(z'-m))`$ 关于 $`z'`$ 单调递减、恒不超过 1。**相对比例完全不受 sink 影响**：sink 不出现在分子里，$`w_j/w_k=\exp(z_j-z_k)`$ 与它无关，表里 sink 取 1.5 与取 None 两行的比例同为 0.731059 : 0.268941（即 0.50648 : 0.186324），份额被整体缩到 0.692804。

![sink 只加在分母上：相对比例一点不变，能变的只有「加起来的总额」](../diagrams/ch28-fig-attn-sink.png)

> *图注：同一组 logits $`[2.0, 1.0]`$，只改 sink 一个数。sink 取 $`-\infty`$（无 sink）时总质量 1.00000000，退化成普通 softmax；sink 取 1.5 时两个权重的**比例一点没变**（0.50648 对 0.186324，与 0.731059 对 0.268941 同比例），但加起来只有 0.692804——sink 拿走 0.307196；sink 取 10.0 时总质量 0.00045866，这个头这一拍几乎不看任何东西；再往大取（20.0）趋近 0，往小取回到 1.0。表里「总质量」这一列就是每个头实际花掉的注意力，也是这一件存在的理由：不给它这个权利，任何头都必须把 1 分完。*

本仓的可读版在 ROCm 路径的在线 softmax 里（`vllm/v1/attention/ops/rocm_aiter_mla_sparse.py:L1194-L1201`）：

`l_final = l_i·alpha + exp(sink − m_final)` 就是那个「只进分母」的字面形态：分子（`acc_o`）里没有对应的 value 项。三处代码事实要分清：**论文说这一件属于 HCA 层**，而两侧实现里 `attn_sink` 都是**每层都有**的参数，有没有真值取决于检查点权重——本仓的初值是负无穷（`vllm/models/deepseek_v4/attention.py:L221-L224`，`exp(−inf)=0` 等价于「无 sink」），官方参考实现是未初始化的 `torch.empty`（官方参考实现（DeepSeek-V4-Pro inference/model.py:L456））。谈默认行为时要写「取决于检查点权重」，不要把这件说成 HCA 独有的代码结构。官方那条最短的落法在核里：sink 在 online softmax 收尾时加进累加和、而分子不加（官方参考实现（DeepSeek-V4-Pro inference/kernel.py:L345-L346））。

**伪码：sink 只进分母**

```python
def softmax_with_sink(logits, sink):
    m = max(max(logits), sink)
    num = exp(logits - m)
    den = num.sum() + exp(sink - m)   # sink 只在这里出现
    return num / den                  # 总质量 = num.sum() / den < 1
```

它钉住的不变量是「总质量 ≤ 1 且相对比例与 sink 无关」：分子的形状不变，多出来的那一项只改变缩放。

## 第五件：四条流残差凭什么不塌

现在把镜头推进 L0 图「GPU 执行臂」列模型层那一格的内部：两次子层（注意力与 FFN）被残差串起来，这件事本身不新鲜（[第 23 章](../../ch23-model-layer-assembly/narrative/chapter.md)立过）。V4 换掉了残差的形式：残差流从 1 条**扩成 $`n_{hc}=4`$ 条**，每半层做一次「读入聚合 → 子层 → 写回散开」，而残差自带一项**流间混合**。旧设计是「一条流加回去」，靠 $`x+F(x)`$ 里那条直通线（恒等映射）让信号与梯度跨层不衰减。把流扩成 4 条、连接花样变多，这条直通线就保不住了——多流残差这套做法叫 mHC（Manifold-Constrained Hyper-Connections，arXiv:2512.24880），它的前身是 Hyper-Connections（arXiv:2409.19606）：后者把残差流扩成 $`n`$ 条、实验最高试到 8、默认 4，想同时缓解梯度消失与表示塌缩两边难兼顾的处境；代价由 mHC 的摘要点名：这种多样化连接破坏了残差连接固有的恒等映射性质，导致严重的训练不稳定与受限的扩展性（arXiv:2512.24880 摘要原句），V4 报告也说明朴素的 HC 在堆多层时数值不稳定。

药方不是放弃多流，而是**约束**。V4 的更新式（arXiv:2606.19348 §2.2 Eq.(1)，符号用报告的 A/B/C）：

```math
X_{l+1} = B_l X_l + C_l \mathcal{F}_l(A_l X_l)
```

其中读入映射 $`A_l`$ 把 $`n_{hc}`$ 条流聚成子层的一路输入，$`C_l`$ 把子层输出散回 $`n_{hc}`$ 条流，而残差自带的那项 $`B_l`$ 被关进一个集合（Eq.(2)）：

```math
B_l \in \mathcal{M} \coloneq \{ M \in \mathbb{R}^{n \times n} \mid M\mathbf{1}_n = \mathbf{1}_n,\ \mathbf{1}_n^T M = \mathbf{1}_n^T,\ M \geqslant 0 \}
```

这里的 $`n`$ 指**残差流条数**，即本章的 $`n_{hc}`$（论文 Eq.(2) 就写作 $`n`$，与本章别处的序列长度 $`n`$ 同名不同义）。这个集合就是**双随机矩阵**全体（非负、每行和为 1、每列和为 1），也叫 Birkhoff 多面体；置换矩阵是它的顶点，恒等矩阵也在里面。

为什么偏偏是这个集合，三条性质一起回答（这三条出自 mHC 原论文 §4.1：只有范数那条留下了原短语 the spectral norm … is bounded by 1，另两条是转述；下面把背后的推导补上）。先给一句话直觉：**谱范数就是这个矩阵最多能把一个向量放大多少倍**——把矩阵在各个方向上对向量的放大倍数都算出来（这些数叫奇异值），最大的那一个就是谱范数；双随机的行和 1 保证不缩、列和 1 保证不胀，所以这个放大倍数恰好被钉在 1 上。三条性质：

<!-- trace: ch28-m12 -->
| 步骤 | 动作 | 关键数值 | 判定 |
|---|---|---|---|
| 双随机判定 | 矩阵 [[0.7,0.3],[0.3,0.7]] 的行和与列和 | 行和 [1.0, 1.0]、列和 [1.0, 1.0]、非负为真 | 双随机判定为真 |
| 谱范数 | 两个双随机矩阵的奇异值 | 一个得 [1.0, 0.4]，谱范数 1.0；一个得 [1.0, 0.264575, 0.264575]，谱范数 1.0 | 恰好等于 1（不是巧合：1 必是特征值，列和再压住上界） |
| 反例 | 矩阵 [[0.9,0.1],[0.2,0.8]]（列和 [1.1, 0.9]） | 谱范数 1.009583 大于 1 | 列和不等于 1 时谱范数就大于 1：最坏方向上最多放大 1.009583 倍（不是每个方向都被放大） |
| 反例的反复自乘 | 同一矩阵的幂次谱范数 $`\|M^k\|_2`$（指数 $`k`$ 取 1、2、3、5、9、17、33） | 1.009583 → 1.018627 → 1.026639 → 1.038734 → 1.049989 → 1.053848 → 1.054092 | 列出的每个幂都大于 1（最小 1.009583），但增幅逐次变小、趋近 1.054092 这个上确界：固定矩阵反复自乘会饱和、不是指数放大；逐层各是一个矩阵时上界才是子乘性的 |
| 封闭性 | 双随机矩阵相乘还在集合内 | 自乘得 [[0.58, 0.42], [0.42, 0.58]]（行列和 [1.0, 1.0]，谱范数 1.0）；三阶同理 | 复合仍在内，深堆叠稳 |
| 非扩张 | 同一组流、两种混合矩阵 | 残差矩阵的 Frobenius 范数 2.5（谱范数量的是「最多把向量放大几倍」，这里量的是矩阵自己的长度，Frobenius 范数 = 各元素平方和的平方根）：双随机混完 1.537856（比值 0.615142）；反例矩阵混完 2.076656（比值 0.830662） | 双随机这一档不放大 |
| 恒等映射回归 | 取双随机集合的顶点：恒等矩阵 | 恒等矩阵乘上流 = 流本身（逐位相同为真） | 多流退化成单流残差的那条「加回去」 |

第一行的两条论证可以一行写清：行和为 1 说明全 1 向量是特征值 1 的特征向量，于是谱范数不小于 1；列和为 1 再给出上界，用的是范数不等式

```math
\|B\|_2 \le \sqrt{\|B\|_1 \|B\|_\infty}
```

（1-范数是最大列和、无穷范数是最大行和）；两头夹住，恰好等于 1。封闭性则是

```math
(B_1B_2)\mathbf{1} = B_1\mathbf{1} = \mathbf{1}
```

加上「非负乘非负仍非负」，复合之后还在集合里。反例把必要性钉死：列和不等于 1 时谱范数 1.009583，同一个混合矩阵反复自乘，放大率单调增、迅速饱和在 1.054092（表里最右那个值）。要留意这里的两件事不是一回事：固定一个矩阵反复用，放大是有界的（所以上面那串数会停下来）；真正的深堆叠是**每层一个矩阵**，这时上界走的是子乘性：

```math
\left\|\prod_l B_l\right\|_2 \le \prod_l \left\|B_l\right\|_2
```

每一层都可能乘上自己的放大因子，层数越多上界越高——这才是「多流会飘」的算术形态，也是「约束而不是放弃多流」这句话的全部内容。

![四条残差流的半层回路：读入聚合、子层、写回散开，流间混合矩阵被关进 Birkhoff 多面体的笼子里](../diagrams/ch28-fig-mhc-manifold.png)

**伪码：半层的 mHC 读写**

```python
def mhc_half_layer(X, F, A, B, C):        # X: [n_hc, d]
    sub = F(A @ X)                        # 读入：聚成子层的一路输入
    return B @ X + C @ sub                # Eq.(1)：流间混合 + 写回散开
```

它钉住的不变量是「混合项不放大」：$`B`$ 的谱范数恰为 1，且双随机集合对乘法封闭，所以无论堆多少层，残差带的范数都不会被混合矩阵放大。本仓那份可读的 torch 回退把这一式写成两行 einsum（`vllm/model_executor/kernels/mhc/torch.py:L94-L106`：`mixed_residual = einsum("...ij,...ih->...jh", comb_res_mix, residual)` 就是把残差按混合矩阵混一遍，`post_term = post_layer_mix * x` 就是 $`C_l\mathcal{F}_l(\cdot)`$，两者相加）。这两个入参名是下游 `mhc_post_torch` 的写法，对应的就是前面 `mhc_pre_torch` 返回的 `comb_mix` 与 `post_mix`（同一个张量在下游换了个名字，别当成又一张矩阵）。方向要当场说清：这个 einsum 收缩的是 `comb_res_mix` 的行下标，算出来是 $`\mathrm{comb}^{\mathsf T}X`$——代码里存的混合矩阵是论文 $`B_l`$ 的转置（双随机集合对转置封闭，与 Eq.(1) 同族，所以「混一遍」这件事的性质不变）。

## 第五件（续）：三张映射当场算出来

$`A/B/C`$ 不是三张固定的权重表，而是**每层当场生成**的。生成原料是残差的展平态：把 $`n_{hc}`$ 条流摊平成一个 $`1\times n_{hc}d`$ 的向量，做一次**没有增益**的 RMSNorm（只按均方根缩放、不学缩放因子），再乘一个大矩阵，一口气吐出 $`(2+n_{hc})\cdot n_{hc}`$ 个数——$`n_{hc}`$ 个读入参数、$`n_{hc}`$ 个写回参数、$`n_{hc}^2`$ 个混合参数（arXiv:2606.19348 §2.2 Eq.(3)-(5)）：

```math
\tilde{A}_l = \alpha_l^{\mathrm{pre}} \cdot (\hat{X}_l W_l^{\mathrm{pre}}) + S_l^{\mathrm{pre}}
```

```math
\tilde{B}_l = \alpha_l^{\mathrm{res}} \cdot \operatorname{Mat}(\hat{X}_l W_l^{\mathrm{res}}) + S_l^{\mathrm{res}}
```

```math
\tilde{C}_l = \alpha_l^{\mathrm{post}} \cdot (\hat{X}_l W_l^{\mathrm{post}})^T + S_l^{\mathrm{post}}
```

```math
\hat{X}_l = \mathrm{RMSNorm}(\mathrm{vec}(X_l))
```

这里 $`\hat X_l`$ 是残差展平后做一次无增益 RMSNorm 的结果；$`\operatorname{Mat}(\cdot)`$ 是把 $`n_{hc}^2`$ 个数摆成 $`n_{hc}\times n_{hc}`$ 的混合矩阵，也就是伪码里那个 reshape；$`\alpha`$ 是三条支路各自的可学习门控（初始化很小，决定「输入相关的动态项」占多少），$`S`$ 是对应的静态偏置（门控为 0 时映射退化成它）。三条 raw 参数里只有 $`\tilde C_l`$ 写转置：$`\hat X_lW_l^{\mathrm{post}}`$ 算出来是 $`1\times n_{hc}`$ 的行向量，转成 $`n_{hc}\times 1`$ 的列向量之后，$`C_l\mathcal{F}_l(\cdot)`$ 才凑得出 $`n_{hc}\times d`$；$`\tilde A_l`$ 不写转置，因为它本身就是读入用的 $`1\times n_{hc}`$ 行向量。三条 raw 参数再各过一道约束（Eq.(6)(7) 与 Eq.(8)）：

```math
A_l = \sigma(\tilde{A}_l), \qquad C_l = 2\sigma(\tilde{C}_l)
```

```math
M^{(t)} = \mathcal{T}_r(\mathcal{T}_c(M^{(t-1)})), \qquad B_l = M^{(t_{\max})}
```

$`\sigma`$ 是 sigmoid：读入压进 $`(0,1)`$（每个读入权重各自小于 1、不会退化成 0 映射；整体的幅度约束不落在这一项上，而在 $`B_l`$ 的谱范数与 $`C_l`$ 的 2 倍上限）、写回乘 2 压进 $`(0,2)`$（放大上限被钉在 2 倍）；两条映射都有了正值下界，都不会退化成 0 映射。混合矩阵走的是第三条路——迭代投影进双随机集合，下一节专讲。

三个细节全在这十几行里：`mixes * torch.rsqrt(sqrsum / (hc_mult*hidden_size) + rms_eps)` 把 RMSNorm 的缩放折进矩阵乘（展平、无权、不单独占一步）；`pre_mix` 是 `sigmoid + eps`、`post_mix` 是 `sigmoid * 2`（那个 2 在核里是硬编码的 `hc_post_mult_value`）；`comb_mix` 是「先 softmax 再列归一、之后重复 $`t_{\max}-1`$ 轮行列交替」，每一步的分母都加一个 1e-6 的保护项。`layer_input` 那一行就是 Eq.(1) 的 $`A_lX_l`$：把 $`n_{hc}`$ 条流按读入权重加权求和成一路。官方参考实现把同一段装在一个核里（官方参考实现（DeepSeek-V4-Pro inference/kernel.py:L391-L396）的三行分别是 σ、2σ 与混合切片，L401-L423 是 softmax 加行列交替），三处切片顺序一致。

**伪码：参数生成与三张映射（sec1 静态 → sec2 动态）**

```python
# sec1：门控取 0 时三张映射退化成静态偏置 S（与输入无关的常量）
# sec2：动态项上场：展平态一次矩阵乘，按可学习门控 α 混进 S
def hc_maps(X, fn, scale, base, n_hc, sinkhorn_iters, eps):
    x = rmsnorm_no_gain(flatten(X))            # 无权 RMSNorm，缩放折进下一步
    mixes = linear(x, fn)                      # 一次矩阵乘出 (2+n_hc)*n_hc 个数
    A = sigmoid(mixes[0:n_hc] * scale[0] + base[0:n_hc]) + eps
    C = 2 * sigmoid(mixes[n_hc:2*n_hc] * scale[1] + base[n_hc:2*n_hc])
    B = sinkhorn(reshape(mixes[2*n_hc:], n_hc, n_hc) * scale[2] + base[2*n_hc:],
                 iters=sinkhorn_iters, eps=eps)
    return A, B, C
```

它钉住的不变量是三张映射的值域与双随机性：$`A`$ 恒在 $`(0,1)`$、$`C`$ 恒在 $`(0,2)`$、$`B`$ 恒在 Birkhoff 多面体里——raw 参数无论怎么学，都不会把残差写没或写爆。

## 第五件（收尾）：为什么是 20 轮

把任意非负矩阵变成双随机矩阵，最省事的办法是**交替归一**：先把每行拉到和 1，再把每列拉到和 1，然后再拉行、再拉列，一轮一轮逼近。这就是 Sinkhorn-Knopp 迭代（起源是 Sinkhorn 1964 年的定理：任何全正矩阵经正对角缩放可以变成双随机，交替归一就是它的构造性证明）。这套迭代用在网络里有个前提：它必须便宜、可迭代、只在前向用——因为它作用在参数的中间量上，不需要可微。

迭代确实在收敛，但收敛的终点不是「精确」：

| 轮次 | 动作 | 关键数值（行、列偏差） | 判定 |
|---|---|---|---|
| 第 1 轮 | 行使和归 1 再列使和归 1 | 行偏差 0.02756985、列偏差 1.05e-06 | 列和当轮就归 1（列偏差恒在保护项地板附近） |
| 第 2 轮 | 同上 | 行偏差 0.00839717、列偏差 1.02e-06 | 偏差逐轮下降 |
| 第 3 轮 | 同上 | 行偏差 0.00255908、列偏差 1e-06 | 每轮约缩到前一轮的三分之一 |
| 第 4 轮 | 同上 | 行偏差 0.00078041、列偏差 1e-06 | 单调降（0.02756985 到 0.00078041） |
| 第 5 轮 | 同上 | 行偏差继续按约 1/3 的比例收缩、列偏差 1e-06 | 还没够到地板：收尾的是列归一，列偏差恒贴地板、行偏差要更多轮才降到它（见下行） |

论文对这个数字的原话是「我们选 20 作为实用值」（as a practical value），不是「迭代到收敛」。为什么有地板：每一步的分母都加一个 1e-6 的保护项（防止除零，同时给矩阵一个正值下界），所以偏差不可能到 0；对残差流混合的实际影响在行和列和不守恒的 0.0001% 量级。**代价是每次半层一次 4×4 的 20 轮交替归一**，与一次矩阵乘相比不算什么，但它是「每半层多出来的固定开销」之一。

本仓与官方参考实现的第一步顺序一致（先 softmax 再列归一，之后重复迭代上限减一轮），论文书面写的是「先列后行」：极限相同，20 轮内的定点略有差别。这类差异不必抹平，讲清哪份文档怎么写的就够了。

**伪码：Sinkhorn-Knopp 投影**

```python
def sinkhorn(B_tilde, iters, eps):
    M = softmax(B_tilde, axis=-1) + eps          # 起点：指数（这里用 softmax 吸收行归一）
    M = M / (M.sum(axis=-2, keepdim=True) + eps) # 列归一：列和当轮归 1
    for _ in range(iters - 1):
        M = M / (M.sum(axis=-1, keepdim=True) + eps)  # 行归一
        M = M / (M.sum(axis=-2, keepdim=True) + eps)  # 列归一
    return M                                      # 双随机，但不是精确投影
```

它钉住的是「迭代上限是折中不是收敛判据」：分母每次都加保护项，偏差只能降到地板；20 轮这个数字的出处是论文的实用值，config 的 `hc_sinkhorn_iters` 与它互证。

## 出口：四流收尾、hc_head 这件自造件

残差带走到主干末尾要收，这里先补一张符号对照——同一组映射在三份文档里有三种写法，读 V4 报告、读 mHC 原论文、读代码时各会撞上一种：

| 角色 | V4 报告（§2.2） | mHC 原论文 | 实现侧 |
|---|---|---|---|
| 读入（把 $`n_{hc}`$ 条流聚成子层输入） | $`A_l=\sigma(\tilde A_l)`$ | $`H_l^{pre}=\sigma(\tilde H_l^{pre})`$ | `hc_scale[0]`（动态门控）、`hc_base` 前段（静态偏置） |
| 流间混合（残差自带那一项） | $`B_l`$ 属于 Birkhoff 多面体 | $`H_l^{res}=\mathrm{Sinkhorn}(\tilde H_l^{res})`$ | `hc_scale[2]`、`hc_base` 末段；迭代上限来自 `hc_sinkhorn_iters` |
| 写回（把子层输出散回各流） | $`C_l=2\sigma(\tilde C_l)`$ | $`H_l^{post}=2\sigma(\tilde H_l^{post})`$ | `hc_scale[1]`、`hc_base` 中段；乘的那个 2 在核里硬编码 |

还有一处实现细节值得记：$`A`$ 在实现里是 `σ(Ã) + eps`，多出来的那个 eps 给门控一个严格正的下界（读入权重不能全零）。

出口本身有两步，顺序不能讲反：**先把展平后的残差拷一份出去**（多预测一步那件要用 $`hc\_head`$ **之前**的残差，4 条流的信息在那里还没丢），**再**用 `hc_head` 把 4 条流按 sigmoid 门控加权求和压回 1 条，然后才做最后一层归一化、算 logits。这个 `hc_head` 是 V4 自己的发明件：mHC 只定义了多流的读写回路，怎么收尾回单流是 V4 加的（官方参考实现（DeepSeek-V4-Pro inference/model.py:L728-L735）：`pre = sigmoid(mixes * hc_scale + hc_base) + hc_eps`，再按这份权重把各流加权求和；注意出口只有 σ、**没有 Sinkhorn**，单流不需要双随机）。入口那一侧还有一个首层特判：第一层的入参还是 2D 的 $`(T,H)`$，要先在核里广播成 4 条流；之后的层入参本身就是残差。

## 第六件：MoE，切得更细，留一个永远算

模型层那一格里，注意力半层之外的另一半是 FFN，算力的账有一半记在这里。MoE（混合专家）的老思路是把一个大的 FFN 换成一池子小专家，每个 token 只挑几个算：参数容量与每 token 算力就此解绑（这个思路出自 2017 年的稀疏门控专家层，arXiv:1701.06538）。DeepSeekMoE 在此基础上加了两板斧（arXiv:2401.06066 §3.1-§3.2），V4 沿用。**记号先对齐**：这两节按 DeepSeekMoE 原文用 $`m`$ 记专家的**细粒度分割因子**——与前面 CSA/HCA 的压缩率 $`m`$ 同名不同义（那件把 $`2m`$ 个位置压成一条，这件把每个专家按 $`m`$ 份切细，专家总数乘 $`m`$）。同样要说的还有 $`h`$：下式里的 $`h_t^l`$ 是这一层 MoE 的**输出**（DSmoe 原文的写法，进 MoE 的输入叫 $`u_t^l`$），与前面 $`h_t`$ 表示的那一行隐状态、以及 MTP 那节的 $`h'^k_i`$ 都不是同一个东西。还有一处口径要在这里分开：DeepSeekMoE 的式子把共享专家算在总池之内（总专家数 $`mN`$、每 token 激活 $`mK`$ 个是含共享的，路由只在 $`K_s`$ 之后的池子里挑 $`mK-K_s`$ 个），而 config 的 `n_routed_experts=256`、`num_experts_per_tok=6` 只数路由专家、`n_shared_experts=1` 另加（两支口径差一个 $`K_s`$）。下面按原文讲式子、按 config 讲数字，数到「每 token 激活几个」时先看清是哪支口径。

先看标准 MoE 层（DeepSeekMoE Eq.(3)-(5)）：门控给每个专家打一个分，只有 top-$`k`$ 的专家拿到自己的分值，其余置 0，输出是专家输出的加权和再加残差：

```math
h_t^l = \sum_{i=1}^{N} g_{i,t}\, \mathrm{FFN}_i(u_t^l) + u_t^l
```

```math
g_{i,t} = \begin{cases} s_{i,t}, & s_{i,t} \in \mathrm{Topk}(\{s_{j,t} \mid 1 \le j \le N\}, K) \\ 0, & \mathrm{otherwise} \end{cases}
```

```math
s_{i,t} = \mathrm{Softmax}_i\left({u_t^l}^\top e_i^l\right)
```

**板斧一：细粒度切分**（DeepSeekMoE Eq.(6)-(8)）。把每个专家的中间维砍到原来的 $`1/m`$、专家总数乘 $`m`$、每 token 激活数也乘 $`m`$：每 token 的算力一分没多，但「可选的组合」多了很多。

```math
h_t^l = \sum_{i=1}^{mN} g_{i,t}\, \mathrm{FFN}_i(u_t^l) + u_t^l
```

**板斧二：共享专家隔离**（DeepSeekMoE Eq.(9)-(11)）。留 $`K_s`$ 个专家**无条件计算**——式子里它那一项根本没有门控：

```math
h_t^l = \sum_{i=1}^{K_s} \mathrm{FFN}_i(u_t^l) + \sum_{i=K_s+1}^{mN} g_{i,t}\, \mathrm{FFN}_i(u_t^l) + u_t^l
```

```math
g_{i,t} = \begin{cases} s_{i,t}, & s_{i,t} \in \mathrm{Topk}(\{s_{j,t} \mid K_s+1 \le j \le mN\}, mK - K_s) \\ 0, & \mathrm{otherwise} \end{cases}
```

前 $`K_s`$ 个专家负责把公共知识兜住（论文的措辞是「捕获并整合跨上下文的公共知识」，从而减轻其余专家之间的冗余），路由只在它们之后的 $`mN-K_s`$ 个专家里挑 $`mK-K_s`$ 个。

**伪码：MoE 一拍（细粒度 + 共享专家）**

```python
def moe(x, gate, experts, shared, K_s, K):
    s = softmax(x @ e_centers.T)                 # DSmoe Eq.(5) 门控分
    g = zeros_like(s)
    picked = topk_indices(s[K_s:], K - K_s) + K_s # DSmoe Eq.(10) 路由只在共享专家之后挑（论文口径 K 含共享专家；config 口径的 K 只数路由专家，共享那 1 个另加）
    g[picked] = s[picked]                        # DSmoe Eq.(4) 只有 top-k 拿到分值，不重新归一
    y = sum(g[i] * experts[i](x) for i in range(len(experts)))   # DSmoe Eq.(6)
    y += sum(shared[i](x) for i in range(K_s))   # DSmoe Eq.(9) 第一项没有门控
    return y + x
```

它钉住两个不变量：算力不变（激活专家数乘 $`m`$ 的同时每个专家的中间维除以 $`m`$），以及共享项对门控的偏导恒为 0。

### V4 换掉的三样东西

V4 在路由上有三处改动（arXiv:2606.19348 §2.1），前两处在这里讲，第三处（hash 路由）单独一节。**其一，亲和分的激活函数从 Sigmoid 换成 Sqrt(Softplus)**：sigmoid 会把大 logits 一律压到 1 附近，专家之间分不出高下（logit 取 8 时 sigmoid 给 0.999665，与 logit 取 3 的 0.952574 几乎没差别）；softplus 是另一个形状（它的定义就是 $`\log(1+e^x)`$：恒正、上不封顶，可以看成 ReLU 的平滑版，所以 logits 再大它也照长），开根号再把分布拉平一点。**其二，负载均衡不再写进损失函数**，而是给每个专家一个修正偏置，它**只参与选择、不参与权重**：偏置帮助均衡「选谁」，但给多少权重仍从无偏的分数里取。这不是新发明，出处是 DeepSeek 2024 年的 auxiliary-loss-free 策略（arXiv:2408.15664），V4 又加了一条很轻的序列级均衡损失兜极端不均衡。

先对齐一处口径：本节路由表里的权重是再归一过的（选中项的权重加起来等于 1），这与前面按 DSmoe 原式字面讲的「不重新归一」不同——前半节照原式演示，本节照 V4 的实测口径。再归一是 config 的 `norm_topk_prob` 说了算，两侧实现都按它走（本仓 `vllm/models/deepseek_v4/nvidia/model.py:L550` 的 `renormalize = config.norm_topk_prob`、`L723` 传进路由核；官方参考实现（DeepSeek-V4-Pro inference/model.py:L581-L582）在非 softmax 打分下 `weights /= weights.sum(-1, keepdim=True)`）。

```python
def router_step(gating_output, bias, topk, hash_table=None, input_tokens=None):
    scores = sqrt(softplus(gating_output))          # 亲和分：Sqrt(Softplus)
    if hash_table is not None:                      # 最前 3 层：查表派单
        expert_ids = hash_table[input_tokens]
    else:                                           # 其余层：按分数挑
        _, expert_ids = topk(scores + bias, k=topk) # 选择用「带偏分数」
    weights = scores.gather(1, expert_ids)          # 权重永远取自「无偏分数」
    return weights / weights.sum(-1), expert_ids
```

它钉住两个不变量：**选择用带偏分数、权重永远来自无偏分数**，所以均衡修正进不了权重分布；hash 那一路只换掉「选谁」这一步，权重照样现算。

### 最前 3 层：连挑都不挑，按 token id 查表

第三处改动在最前面几层：V4 把最前若干层的稠密 FFN 换成用 hash 路由的 MoE，而所谓「hash 函数」是按**输入 token 的 id**查一张预先定好的表（arXiv:2606.19348 §2.1 原话是「按与输入 token id 有关的预定义哈希函数决定目标专家」）。论文把这条路由式写作 $`\mathrm{hash}(x_t)`$，输入 $`x_t`$ 是原始 token 而不是隐状态。这条路线的出处是 2021 年的 Hash Layers（arXiv:2106.04426）：按当前 token 的哈希值选一组权重，**不需要路由参数、不需要目标函数里的均衡项、也不需要复杂的分配算法**，论文还报告 balanced 与 random 指派表现相近、学习式聚类反而更差。

| 真实口径 | 最前 3 层用 hash、表形状 | 生效层数 3、词表 129280，表是 [129280, 6] | 运行时只是一次 gather |

最后一行是 V4 的落地形态：config 口径 `num_hash_layers=3`、词表 129280、每 token 挑 6 个，所以表就是 129280 行乘 6 列的整数，随权重一起装载，运行时每个 token 查一行。**必须点破的一点**：hash 只决定**选谁**，从来不是「这几层没有门控」——权重仍然从这一层的无偏亲和分里取（上面那段代码的 hash 分支最后一行就是 `weights = scores.gather(...)`）。代价也在同一句里：选谁完全脱离内容，同一层里只要 token id 相同就派同一批专家，没法按语境调整；这条路线换来的是「没有路由参数、没有均衡项」的简单，代价是「不看内容」。另外，论文没说为什么只有前 3 层用 hash，正文不替它编理由。

![最前 3 层按 token id 查表派单：一张整数表决定选谁，权重仍从当层无偏分数现算](../diagrams/ch28-fig-hash-route.png)

> *图注：左边是一列 token id（只用到 id，与隐状态无关），指向中间一张整数表（玩具口径 6 行 2 列，命中的行高亮），一次 gather 出专家号；右侧是派单结果三行（token 4 得专家 [3, 0] 权重 [0.818182, 0.181818]，token 1 得 [0, 2]、[0.65, 0.35]，token 5 得 [1, 2]、[0.25, 0.75]）。虚线框里画的是这一层不走的那条路：若改成打分的 top-2，同一批 token 抽到的是 [[1, 3], [0, 2], [2, 3]]，与查表结果不同，说明 hash 的选择与门控分数完全无关；框里的打分框被红叉划掉，但仍标注「分数不参与选择、依然决定权重」。下部左栏强调「表只决定选谁」并指出这不是「没有门控」，右栏给出真实尺度（生效 3 层、表 [129280, 6]）与「论文没说为什么只有前 3 层」。*

本仓的实现是把表当权重装载：前 `num_hash_layers` 层建 `gate.tid2eid`（形状 `[vocab_size, num_experts_per_tok]` 的整数表，`vllm/models/deepseek_v4/nvidia/model.py:L571-L590`），其余层改挂 `e_score_correction_bias`（auxiliary-loss-free 那个偏置）。官方参考实现同样：`self.hash = layer_id < args.n_hash_layers`、表 `self.tid2eid`、查表 `indices = self.tid2eid[input_ids]`、权重 `weights = original_scores.gather(1, indices)`（官方参考实现（DeepSeek-V4-Pro inference/model.py:L556、L559、L576-L580））。

**伪码：hash 路由**

```python
def hash_route(gate_scores, input_ids, tid2eid, topk):
    expert_ids = tid2eid[input_ids]              # [M, topk] 一次查表，与隐状态无关
    weights = sqrt_softplus(gate_scores).gather(1, expert_ids)   # 权重仍现算
    return weights / weights.sum(-1, keepdim=True), expert_ids
```

它钉住的不变量是「选择的输入是 token id」：选择与隐状态、与门控分数无关（因而不需要均衡损失项），但权重仍由当层亲和分决定。

## 第七件：MTP，顺手多预测一步

自回归训练每个位置只有一个标签，监督信号偏稀；投机解码又需要一个便宜的草稿器。V4 顺手把两件事一起办：在主干后面再接一档模块，让它多预测一步（arXiv:2412.19437（DeepSeek-V3 报告）§2.2 的设计，arXiv:2606.19348 §2.1 声明 **without modification** 沿用）。

模块的形状是「拼接 → 一个 Transformer 块 → 共享的输出头」（V3 报告 §2.2 Eq.(21)-(23)）：

```math
h'^k_i = M_k\left[\mathrm{RMSNorm}(h^{k-1}_i);\ \mathrm{RMSNorm}(\mathrm{Emb}(t_{i+k}))\right]
```

```math
h^k_{1:T-k} = \mathrm{TRM}_k(h'^k_{1:T-k})
```

```math
P^k_{i+k+1} = \mathrm{OutHead}(h^k_i)
```

损失是本档位置的交叉熵，按深度加权后加到总损失上（V3 报告 §2.2 Eq.(24)(25)；$`D=1`$、$`\lambda=0.3`$ 是 V3/V4 的超参）。这里要分清论文原话与本章读法：论文只留下公式行，没有留下定义 $`T`$ 的那句话，所以下面这条是本章的读法（把 $`T`$ 按 1 基记法数序列里的 token 数，上界写成 $`T+1`$ 是给「数据里还留着最后一个标签位」留的位置）：本节的玩具只有 5 个 token、$`t_4`$ 之后没有标签位，所以 $`T=5`$、$`k=1`$ 代进去只有 3 个目标（0 基下标 $`t_2,t_3,t_4`$），与下标对齐表那三行一致——最后一个隐藏位置 $`h^1_3`$ 算出来却没有目标，那是记号的边界，不是实现缺陷：

```math
L^k_{\mathrm{MTP}} = \mathrm{CrossEntropy}(P^k_{2+k:T+1},\ t_{2+k:T+1}), \qquad L_{\mathrm{MTP}} = \frac{\lambda}{D}\sum_{k=1}^{D} L^k_{\mathrm{MTP}}
```

三条口径要讲清。**embedding 层与输出头都与主模型共享**（新增参数少）。**是「顺序」而不是并行独立多头**：$`D`$ 个模块一档一档接下去，第 $`k`$ 档吃第 $`k-1`$ 档的输出，每一档都保持完整的因果链；论文明确把这条与「用 n 个独立输出头并行预测 n 个 token」的方案区分开（那条路线的代表是 Meta 的并行多头，arXiv:2404.19737）。**推理期两条路**：直接丢弃这些模块（零成本），或者把它们复用作投机解码的草稿器。

![一档 MTP 的数据流：主干尾部残差与第 i+1 个 token 的 embedding 拼接、过因果块、用共享输出头预测 t_{i+2}](../diagrams/ch28-fig-mtp-flow.png)

![主干尾部的分叉：先拷贝、再压扁，顺序反过来就丢掉了四条流的差异](../diagrams/ch28-fig-mtp-fork.png)

> *图注：主干尾部只有一个分叉点，两支的顺序不能反：先把 4 条流的展平态**拷一份**交给草稿器（图上品红那条），**再**过出口的门控加权求和压回单流去算 logits（绿色那条）。细线是四条流、粗线是压回后的单流；反过来的话，这一档拿到的就是一条已经被平均过的残差，4 条流的差异全丢了，草稿器也就失去了与主干同源的意义。这也是「它为什么长在主干里」的答案：它吃的是主干出口的残差，不是另配的一份输入，所以它是主干的一个分支，而不是外挂的独立小模型。这一档只开 1 档（与论文的 $`D=1`$ 一致），推理期可以整档丢掉，也可以留下来起草。*

**伪码：MTP 一档**

```python
def mtp_step(prev_hidden, input_ids, M_k, TRM_k, OutHead, k):
    e = rmsnorm(embed(input_ids.shift(k)))        # 第 i+k 个 token 的 embedding
    h = rmsnorm(prev_hidden)                      # 上一档的隐状态（多流展平态）
    x = M_k(concat([h, e]))                       # Eq.(21)：拼接过投影
    return OutHead(TRM_k(x))                      # Eq.(22)(23)：因果块 + 共享输出头
```

它钉住的不变量是错位关系与因果不偷看：输入错位 $`k`$ 格、目标错位 $`k+1`$ 格，块内因果掩码保证位置 $`i`$ 看不到 $`j>i`$。

## 附账：条目落在哪、没攒满的窗在哪

七件套讲完，把缓存这一侧的坐标补上。同一串 token 有三把尺子叠在一起：原始 token 轴（位置 0 到 $`n-1`$）、压缩块轴（条目号 = 位置除以压缩率）、分页 KV 的槽位轴（块号加槽内偏移）。三件事一次说清：

- **谁产出条目**：只有 `(position + 1) % compress_ratio == 0` 的块尾 token 触发压缩核，其余位置早退（前面那段压缩核的第一行就是这个判断）。
- **条目落在哪**：条目号等于 `position // compress_ratio`，落进分页槽位 `block_number * block_size + pos_after_compress % block_size`：压缩不是另存一份小副本，而是把每个页槽装满 $`m`$ 个 token 的内容，于是每页能装的历史长了 $`m`$ 倍（这也是本仓 `storage_block_size = block_size // compress_ratio` 一行的来历，见 `vllm/v1/kv_cache_interface.py:L404-L417`；槽位映射本身是[第 22 章](../../ch22-slot-mapping-block-table/narrative/chapter.md)的正题，这里只是把条目号接上同一套块表）。
- **没攒满的窗在哪**：留在压缩机自己的状态缓存里等下一拍（kv 写前半、分数写后半），不产出条目、也不进逐 token 的摊销账——它是第四本 KV 账（压缩机 state），按块存、与压缩条目共用同一张物理张量，下一章与另外三本一起算。

![三把尺子量同一串 token：原始 token 轴、压缩块轴、分页槽位轴，底部横带列出三本缓存的宽度](../diagrams/ch28-fig-compress-coords.png)

> *图注：三把尺子共用一套列宽叠放。最上面是原始 token 轴，块尾 token（3、7、11）标着「块尾产出」，只有它们触发压缩核，其余位置早退。中间是压缩块轴：条目号 = 位置 // m，12 个 token 得 3 条。最下面是分页槽位轴，条目按序号落进页槽，未满一窗用虚线框标出「留在压缩机 state 里等下一拍」，框外注明条目与页共享同一张物理张量（块大小因此被页尺寸约束成 4 或 8）。底部那条横带的左半边是三本缓存的宽度：主压缩条目 584B（448 fp8 NoPE 加 128 bf16 RoPE 加 8 fp8 scale）、索引器小头 132B（128 fp8 加 4 fp32 scale，只有压缩率为 4 的层建它）、滑窗 128 条未压缩 KV（恒长）——第四本（压缩机自己的 state）按块存、不进逐 token 摊销账，下一章与这三本一起算；右半边给出 1M 下的条目数：CSA 层 250000 条、HCA 层 7812 条。*

## 对账：七件套各还了多少

回到开账那张靶子，按「在哪本账上、是省还是花」把七件套过一次账：

| 件 | 动的账 | 换算 | 代价（诚实面） |
|---|---|---|---|
| 第一件　压缩（$`m=4`$） | KV 账（条数降 $`m`$ 倍）+ FLOPs 账（每 query 看的条数降 $`m`$ 倍） | 每 token 摊销 584 除以 4，加索引器小头那条 | 分辨率被抹平；块内先后看不见 |
| 第二件　选择（$`k=512`$） | FLOPs 账（每 query 实看条数封顶） | 25 万候选里只看 512 条 | 选择器自己的算力与缓存（132B 一条），还有漏看的盲区 |
| 第三件　HCA（$`m'=128`$） | KV 账（再降 32 倍）+ FLOPs 账（不挑、无选择器开销） | 每 token 摊销 584 除以 128；每 query 全看 7812 条 | 主注意力每 query 条目数多 15.257812 倍（「因此只占一半层」是本书由成本给出的读法，论文未解释交替） |
| 第四件　滑窗（$`n_{\mathrm{win}}=128`$） | **加账** | 43 层乘 128 条乘 576 字节的常数窗（token 数据段口径；含 8 字节缩放是 584 字节） | 每层多存 128 条未压缩 KV，短上下文里最贵 |
| 混合精度存储 | KV 体积账 | 一条 584 字节 = 448 字节 FP8（NoPE）+ 128 字节 BF16（RoPE）+ 8 字节缩放 | 位置那段必须留在 BF16，否则位置精度掉 |
| 第五件　mHC（4 条流） | **不加 KV 账**（残差流宽度是激活不是缓存） | 换来的是训练稳定性 | 每半层多一次参数生成矩阵乘、20 轮 Sinkhorn、4 条流的激活与访存 |
| 第六件　MoE（256 挑 6 加 1 共享） | FLOPs 账（激活参数远小于总参数） | 每 token 只算 6 个路由专家加 1 个共享专家 | 共享专家的算力每个 token 都要付；路由本身有开销 |
| 第七件　MTP（$`D=1`$） | **不加账**（推理期可整段丢弃） | 换来一个与主干同源的草稿器 | 训练多一份损失项；用它做草稿时接受率不好就白算 |

这张表有两个诚实面要写出来。**其一，论文摘要里的 27% 与 10% 是净结果**：里面既有省账（压缩、稀疏、混合精度），也含着花账（滑窗多存 128 条、mHC 多算几条流），不能把七件都说成省账；而且它们是 **V4-Pro** 的端到端数字，本章那张逐层表按 V4-Flash 的 43 层排布算，型号与口径都不同，别把 13.6495% 当成「离 10% 只差一点口径」。**其二，三个数字三个分母**：27% 与 10% 的分母是 V3.2，约 2% 的分母是 BF16 GQA8 基线，混起来引用就是错误陈述。
